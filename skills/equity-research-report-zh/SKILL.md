# 上市公司研究与估值报告全流程

完成一份能独立阅读、结论明确、数字可追溯、模型可复算的报告。任务从原始资料开始，经过经济机制分析和模型选择，最终落到估值判断、监测指标及可推翻条件；写报告只是其中一个环节。

## 开始工作

1. 读取用户指定报告、模板、原始资料、现行模型和最近的修改要求。先确认各文件用途和版本；保留旧成果，在新目录工作。
2. 明确公司及证券、读者与用途、估值日、信息截止时点和时区、业务/权益范围、预测期、输出语言/单位、交付格式。仅询问会改变结论或阻碍工作的关键缺项；其他选择说明假设并推进。
3. 建立研究问题：公司如何赚钱、增长从何而来、现金由谁取得、现价隐含什么、哪些证据会改变判断。按问题安排采集任务，而非先收集所有可找到的资料。
4. 使用 `scripts/init_workspace.py` 初始化新工作目录，填完 `project.json`。该脚本只建立资料和交付结构；它不替代研究、预测或模型实现。

## 数据获取与核对

执行 [原始资料与研究落地](references/data-research.md)。优先公司公告/财报、交易所、监管及统计部门、项目批准文件、原始方法资料。搜索摘要只能用于寻找原件。

- 搜索并保存资料，记录公开时间、期间、版本、下载时间、原件定位和哈希。可用 `scripts/capture_source.py` 留存指定公开URL；API、受限网站和本地文件用环境可用工具取得，仍填相同台账。
- 从原件提取数字，核对单位、币种、税口径、并表范围、重述版本和股权归属；保留原始精度，展示时才舍入。
- 同一资料可用于当前描述，却未必能用于历史回测。截止日之后发布的资料不得回填历史分析。获取成功、资料核实、进入模型，是三个不同判断。
- 输出 `evidence/sources.json`、`facts.json`、`assumptions.json`、`claims.json` 和 `gaps.json`。这些文件供工作和检查使用，不直接粘贴为报告正文。

## 形成判断并建立模型

先将重要事实组成因果链，再执行 [预测与估值建模](references/modeling.md)。每项核心判断写清：少量关键证据 → 经济机制 → 对收入/利润/现金/权益的作用 → 模型处理 → 反证和改变判断的条件。

- 可以形成方向明确的判断。以实质不确定性决定措辞强度，不能因数据尚有空白就把所有结论写成“可能、有待核验”。
- 对缺项依次尝试：补查原件、可复算推导、有依据的区间/代理、情景和反向估值；仍无法确定且足以改变结论的，保留条件结果或缩小判断范围。区间无依据时不要编造上下限。
- 根据行业选择适合的方法。非金融经营企业可优先评估FCFF；金融机构、特殊资本结构或资产价值主导公司需另选方法，解释选择理由。
- 建立同一套可复算预测、现金预算、估值和报告数字输出。历史、研究假设、模型输出保持不同类型。旧结果不约束新结论。
- 方法之间解释差异。共用预测的FCFF与EVA是计算一致性校验；PE等是另一种市场观察。不要把相关结果当成独立投票，也不要任意平均。
- 补证、口径或方法改变后，更新受影响的模型、表格、图和文字判断，重新执行受影响检查。

## 写作与排版

执行 [面向读者的写作](references/writing.md) 和 [交付与检查](references/delivery.md)。叙事路径通常为业务与现金来源 → 行业约束与优势 → 盈利预测 → 估值与现价 → 风险和改变判断的条件；具体章节遵循用户模板。

- 主报告用连贯段落解释研究判断，关键表格承担比较和结果；详细来源、全量预测、核验过程及失败记录分别放附录或底稿。
- 一项限制在定义处说明；只有它会改变当前段落判断时才再次提及。删除没有新增信息的提醒，保留实质限制。
- 若未指定必须遵循的结构，用短摘要先说明核心结论、价值区间/条件、主导驱动、最重要的反转条件。指定模板可以覆盖这一默认安排。
- 若使用条件价值，标题、表注、摘要和最终判断保持一致；避免正文只给“基准估值”，把重要条件藏在后文。
- 模型输出直接生成数值表，避免手工维护多份数字。核对模型到报告的绑定；文字中出现的数字也检查。
- 表格有明确任务、连续编号、期间/单位/范围/事实与预测标识、必要来源和简短解释。叙述性推理写成段落。
- 排版遵循用户参考样式，使用标题样式和可更新目录。渲染最终DOCX/PDF并检查页面、公式、跨页表头、标题和引用；不能仅凭XML或“生成成功”判定排版合格。

## 完成条件

运行 `scripts/check_bundle.py WORKSPACE --stage delivery` 检查机器可查的一致性，再完成实质审阅。详见交付参考中的台账格式与命令。

交付至少包括用户要求的报告、可复算模型及输入、必要原件和台账、独立复算/页面检查记录、研究结论与跟踪条件。向读者明确哪些结果已核实、哪些依赖估计，以及影响最大的条件。助手检验通过不等于经济假设已获证明。

遇到单一渠道失败，尝试适当替代渠道并继续独立工作；重大不可消除缺项必须说明其具体影响。不要用大批泛化声明代替判断，也不要把部分完成说成全流程完成。

## 按需参考

- [长江电力案例](references/changjiang-case.md)：当用户需要理解来源经验、改写案例或水电驱动时阅读；案例数字不得作为新公司的默认参数。
- 脚本只用Python标准库；不依赖特定搜索连接器、Word软件或另一语言版本。环境有相应文档/表格工具时使用；没有时选择可验证的替代途径并记录限制。
- 本skill执行当前用户授权的研究和本地交付；公开发布、建仓、推送和上传遵循用户当次授权。它不是已经能无人值守跑完研究的agent。
